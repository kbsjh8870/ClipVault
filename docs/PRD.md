# ClipVault — PRD (Product Requirements Document)

- 문서 버전: v0.2
- 작성일: 2026-09-25 (최초) / 수정: 2026-09-25
- 작성자: JH

## 1. 배경 및 문제 정의

여러 대의 PC(회사 PC, 집 PC, 노트북 등)를 오가며 작업하는 사용자는 한 기기에서 복사한 텍스트를 다른 기기에서 이어 쓰고 싶을 때, 현재는 별도의 동기화 수단이 마땅치 않다.

- Windows 클립보드 히스토리(Win+V)는 기기 내부에서만 유효하고 기기 간 동기화를 지원하지 않는다.
- 흔히 쓰는 우회 방법은 메신저(카카오톡 '나와의 채팅' 등)에 직접 붙여넣고 전송하는 것인데, 매번 "복사 → 메신저 실행 → 채팅방 진입 → 붙여넣기 → 전송"이라는 능동적인 행동이 필요하다.
- 이 방식은 실제 대화 내용과 뒤섞여 검색이 어렵고, 시간이 지나면 정리가 안 되며, 실수로 다른 사람에게 전송할 위험도 있다.

ClipVault는 PC에서 복사하는 행위(Ctrl+C) 자체를 그대로 캡처하여 다른 등록된 PC로 자동 동기화함으로써, 사용자가 "보내야지"라고 의식적으로 행동하지 않아도 되는 경험을 제공하는 것을 목표로 한다.

## 2. 타겟 사용자 및 페르소나

특정 직업군에 종속되지 않고, 여러 대의 PC를 오가며 컴퓨터 작업을 하는 모든 사용자를 타겟으로 한다. 이해를 돕기 위해 대표 페르소나 3가지를 정의한다.

### 페르소나 A — 재택/사무실 혼합 근무자
- 상황: 주 2~3일은 사무실 PC, 나머지는 재택 PC로 근무
- Pain Point: 회의 링크, 문서 경로, 승인번호 등을 사무실에서 복사해놓고 집에서 다시 찾느라 메일함/메신저를 뒤짐
- 기대: 사무실에서 복사한 것이 집 PC에서 별도 조치 없이 바로 붙여넣기 가능하길 원함

### 페르소나 B — 1인 개발자 / 취업 준비생
- 상황: 데스크톱(주력)과 노트북(외부/카페 작업)을 병행 사용
- Pain Point: API 키, 터미널 명령어, 에러 메시지, 코드 스니펫을 기기 간 옮기는 일이 잦음
- 기대: 개발 중 복사한 스니펫을 다른 기기에서 바로 이어 쓰고 싶음. 민감 정보(키 등)가 오래 남는 것은 부담스러워 자동 삭제를 선호

### 페르소나 C — 학생/대학원생
- 상황: 학교 실습실 PC와 개인 노트북을 오가며 과제/논문 자료 정리
- Pain Point: 실습실에서 찾은 자료 링크나 인용문을 집에서 이어 정리하려면 매번 자신에게 메일을 보내거나 메모 앱에 옮겨 적음
- 기대: 별도 앱을 켜서 옮겨 적는 수고 없이 자연스럽게 이어지길 원함

## 3. 목표 (Goals)

- PC 기기 간 클립보드(텍스트) 동기화를 자동화하여 메신저 우회 방식 대비 압도적으로 편리한 경험 제공
- 최소 예산(무료 티어 인프라)으로 1인 개발이 가능한 범위의 서비스 설계
- 개인정보(민감한 복사 내용)가 무기한 누적되지 않도록 자동 만료(TTL) 정책 적용

## 4. MVP 범위 (1차 구현 vs 이후 확장)

### 4.1 MVP에 포함 (v1, 반드시 만든다)

- 이메일/비밀번호 기반 회원가입 및 로그인
- PC(Windows) 트레이 상주 클라이언트를 통한 클립보드 텍스트 자동 캡처 및 업로드
- 등록된 다른 PC로 실시간(WebSocket) 동기화 알림
- 클립 히스토리 조회(최근 N개) 및 클릭 시 로컬 클립보드로 복사
- 클립 자동 만료(TTL) 및 서버 측 배치 삭제
- 로그인된 기기 목록 조회 및 개별 기기 로그아웃(원격 로그아웃)

### 4.2 MVP 이후로 미룬다 (Out of Scope, 백로그로 이관)

- 모바일(Android/iOS) 클라이언트 — 모바일 OS의 백그라운드 클립보드 접근 제약으로 인해 자동 캡처가 불가능하고, PC 대비 차별화된 가치를 제공하기 어려워 v1에서 제외
- macOS 지원 — 개발 환경에 macOS 기기가 없어 테스트 불가. Java 클립보드 API 자체는 크로스플랫폼이라 추후 macOS 접근이 생기면 재검토
- 이미지/파일 클립보드 지원 — 텍스트만 우선 지원
- 진짜 종단간 암호화(E2E) — v1은 전송 구간 HTTPS + 서버 측 저장 암호화로 시작하고, 트레이드오프를 문서화
- 검색, 태그, 즐겨찾기(고정) 기능

판단 기준: "이게 없으면 핵심 가치(PC 간 자동 동기화)가 성립하지 않는가?"를 기준으로 MVP 포함 여부를 결정했다. 위 4.2 항목들은 없어도 핵심 가치 자체는 온전히 전달된다.

## 5. 핵심 기능 상세

### 5.1 회원가입/로그인
- 이메일/비밀번호로 가입, JWT 기반 인증
- 로그인 시 트레이 앱이 서버에 인증 토큰을 저장하고 재사용

### 5.2 기기 등록
- 트레이 앱 최초 로그인 시 현재 PC를 기기로 자동 등록 (기기명, OS 정보 포함)
- 사용자가 기기명을 직접 지정할 수 있도록 지원(예: "회사PC", "집PC")

### 5.3 클립보드 자동 캡처 및 동기화
- 트레이 앱이 로컬 클립보드 변경을 감지하면 텍스트 내용을 서버에 업로드
- 서버는 같은 사용자의 다른 활성 기기에 WebSocket으로 새 클립 도착을 알림
- 알림을 받은 기기는 트레이 아이콘에 알림 표시. 자동으로 로컬 클립보드를 덮어쓰지 않고, 사용자가 알림/목록을 클릭했을 때만 로컬 클립보드에 반영한다(원치 않는 타이밍에 클립보드가 바뀌는 것을 방지).

### 5.4 클립 히스토리 조회
- 트레이 아이콘 클릭 시 최근 클립 목록 팝업 표시
- 항목 클릭 시 해당 내용을 로컬 클립보드로 복사

### 5.5 자동 만료(TTL)
- 클립은 생성 후 일정 기간(기본값 검토 필요, 예: 7일)이 지나면 자동 삭제
- 사용자가 만료 기간을 설정할 수 있는 옵션 고려(v1.1 이후)

### 5.6 기기 관리
- 로그인된 기기 목록 확인
- 특정 기기 원격 로그아웃(분실/공용 PC 대비)

## 6. 핵심 사용자 시나리오

### 시나리오 1 — 기본 동기화 (페르소나 A)
1. 사용자가 회사 PC에 트레이 앱을 설치하고 로그인한다.
2. 사용자가 집 PC에도 같은 계정으로 트레이 앱을 설치하고 로그인한다.
3. 회사 PC에서 어떤 텍스트를 복사(Ctrl+C)한다.
4. 별도의 추가 행동 없이, 집 PC의 트레이 아이콘에 새 클립 도착 알림이 뜬다.
5. 집 PC에서 트레이 아이콘을 클릭해 목록에서 해당 항목을 클릭하면 로컬 클립보드에 복사되고, 바로 붙여넣기(Ctrl+V)할 수 있다.

### 시나리오 2 — 여러 개 중 원하는 것 골라 쓰기 (페르소나 B)
1. 개발 중 여러 번 복사(에러 메시지, 명령어, 변수명 등)를 반복한다.
2. 다른 PC에서 트레이 아이콘을 클릭해 최근 클립 목록을 확인한다.
3. 목록에서 필요한 항목만 골라 클릭하여 로컬 클립보드에 반영한다.

### 시나리오 3 — 기기 분실/공용 PC 사용 후 (모든 페르소나)
1. 사용자가 실습실 공용 PC 또는 분실 우려가 있는 노트북에서 로그인했던 것을 기억해낸다.
2. 다른 신뢰 기기(또는 웹)에서 기기 목록을 확인한다.
3. 해당 기기를 원격 로그아웃하여 더 이상 클립 동기화 대상이 되지 않도록 한다.

### 시나리오 4 — 네트워크 재연결 (페르소나 A, B)
1. 노트북을 들고 이동하는 동안 네트워크가 끊겨 WebSocket 연결이 끊긴다.
2. 다시 네트워크에 연결되면 트레이 앱이 자동으로 재연결을 시도한다.
3. 재연결 시 그 사이 놓친 클립이 있는지 최근 목록을 다시 조회하여 누락 없이 동기화된다.

## 7. 비기능요구사항

- **보안**: HTTPS 통신 필수, 비밀번호는 해시 저장, 클립 내용은 서버 저장 시 암호화
- **프라이버시**: 클립 내용은 TTL 경과 시 자동 삭제되어 무기한 누적되지 않음
- **가용성**: 개인 프로젝트 규모에 맞는 무료/저비용 인프라로 운영 가능해야 함
- **성능**: 클립보드 변경 후 다른 기기 알림까지 수 초 이내 반영 목표

## 8. 성공 기준

"잘 만들어졌다"를 판단하기 위한 기준을 정량/정성으로 나눠 정의한다.

### 8.1 정량적 기준
- 클립 업로드 시점부터 다른 기기에 알림이 도달하기까지 평균 3초 이내
- 동일 텍스트 재복사 시 중복 레코드 없이 timestamp만 갱신되는 로직이 100% 동작
- 본인이 실제 업무에서 연속 1주일 이상 사용해도 동기화 누락·중복이 발생하지 않음
- TTL 경과 후 24시간 이내 배치를 통해 해당 클립이 실제로 삭제됨

### 8.2 정성적 기준
- 배포된 URL/실행 파일로 실제 데모가 가능한 상태
- 30초 내외의 데모로 "PC 간 자동 클립보드 동기화"라는 핵심 가치를 상대방(면접관 등)에게 전달할 수 있음
- 기술 블로그(Velog)에 설계 의사결정과 트레이드오프(자동 반영 vs 알림, 모바일 제외 사유, 암호화 수준 결정 등)를 논리적으로 설명하는 글을 작성할 수 있음

## 9. 향후 로드맵 (백로그)

- 모바일 대응: 반응형 웹앱(PWA) 형태로 수동 저장/복사 지원 (Android는 Web Share Target 활용 검토)
- macOS 트레이 앱 지원
- 이미지 클립보드 지원
- 검색/태그/즐겨찾기 기능
- 진짜 종단간 암호화

## 10. 설계상 트레이드오프 (참고)

- **자동 반영 vs 알림 후 수동 반영**: 완전 자동으로 클립보드를 덮어쓰는 방식은 편리하지만 예기치 않은 타이밍에 클립보드가 바뀌는 부작용이 있어, v1은 "알림 → 클릭 시 반영" 방식을 채택한다.
- **모바일 제외 결정**: 모바일 OS(Android 10+, iOS)는 백그라운드 클립보드 자동 접근을 정책적으로 차단하므로, 모바일에서는 결국 수동 저장이 필요하다. 이 경우 기존 메신저 우회 방식 대비 차별성이 크지 않다고 판단하여 v1 범위에서 제외했다.
- **암호화 수준**: 완전한 종단간 암호화는 키 관리 복잡도가 높아 v1에서는 서버 측 저장 암호화로 시작하고, 이 결정과 향후 개선 방향을 명시적으로 문서화한다.
